# Drawing controls: Unity scene evidence

Source: `extracted/v3.141/base/assets/bin/Data/data.unity3d`, scene `level4`. Image MonoBehaviour sprite pointers were read as a file ID and 64-bit path ID at byte offset 88 and resolved through the scene's external-file table and `reports/v3.141/sprite-exports.json`. The nine button PNG hashes match their exported sprite records. This is static scene evidence, not a runtime comparison.

| Control | Scene child order and sprite (sharedassets4.assets path ID) |
| --- | --- |
| Tools, GO 360 | shadow 88 `button-shadow`; main 171 `button-bg`; icon 215 `button-icon-tool`; top 165 `button-shine`; pressed 195 `button-press` (initially inactive); stroke 202 `button-stroke` |
| Eraser, GO 73 | shadow 88; main 171; icon 178 `button-icon-elastic`; top 165; pressed 195 (initially inactive); stroke 202 |
| Color, GO 63 | shadow 88; mask 208 `button-bg-color`; outline 152 `button-stroke-color` twice; top 165; pressed 195 (initially inactive). Mask children include pattern and other layers; runtime configuration requires further analysis. |

The three buttons' RectTransforms measure 209 × 209, with centers at y = 235, 0, -235 within `BigToolButtons`. Their normal image children measure 214 × 214. `ManageTools` is 266.12 × 1080; runtime scaling may affect final placement.

`BrushPanel` uses `popup_tools`. Marker, pencil, and fill use `tool_*_bottom` with child images in order `main`, `outline`, `top`. The web intentionally keeps the user's reduced tool selection. `PaletteColors` contains 56 entries using `popup_palette_white`; initial positions advance seven rows at 125 units then one column at 130 units. Each is 110 × 110, and its centered `palette_checked` child is 135 × 135. The 56 serialized Image RGB values match the web palette in the same order (rounded to 8-bit RGB). The second color outline is black with alpha 0.207843; the top shine follows both outlines. Popup activation and the runtime color button mask contents have not been completely verified.

Unity Button serialized events bind the three buttons to `ManageTools.OnButtonTools`, `OnButtonColors`, and `OnButtonEraser`. Metadata links them to native addresses 0x1543160, 0x15438a0, and 0x1543a50 respectively (REA evidence `ev_49bb044cb644f8251a3c1e6e02a4bf251e3e9b6562befe125b5a186bea92cb48`). Bounded ARM64 instructions are in `reports/v3.141/drawing-controls.asm`. OnButtonEraser tests the current brush type against 7, stores the prior type in the adjacent field before setting 7, and restores it when already 7; both other handlers have a matching type-7 restoration path. The interpretation of 7 as eraser follows the extracted BrushTypes enum. Exact popup animations and all called methods remain unverified.

`ManageBigButtons` fields `brushesButtonPressed`, `colorsButtonPressed`, `eraserButtonPressed`, `brushesShinePressed`, `colorsShinePressed`, and `eraserShinePressed` occur in that order. The ARM64 methods called by the three `ManageTools` handlers set the corresponding pressed and shine GameObjects oppositely: `hj`/`hm` for tools, `hk`/`hn` for colors, and `hl`/`ho` for eraser. In the opening branches, the pressed object is enabled and shine disabled; closing or restoring reverses them. Tool and eraser methods additionally call a separate operation on the ButtonTools field, whose effect has not been decoded here. This conclusion is from static calls and field order, not a runtime observation.

`Brush.OnPointerUp` (0x153f40c) checks a condition and, on the non-return path, passes its `brushesPanel` to the same transition function used by `ManageTools` to close the panel. `Palette.OnPointerUp` (0x15447ac) also checks conditions and calls a `ManageTools` transition with `mainPalette`; its complete asynchronous close callback is not yet decoded. For brush images, marker and pencil parent and all three children have 216 × 128 RectTransforms; fill and its children have 209 × 154. Their parent scales are 0.8. The four sprite files have different raw dimensions, so independent `object-fit: contain` shifts their layer geometry; the scene's Image preserve-aspect flag is false, and all four layers use their shared RectTransform.

Correction after the reported misalignment: the exported PNGs are cropped to Unity's sprite texture rectangles, not full sprite frames. Stretching the cropped images to the same RectTransform is therefore incorrect. The original Sprite `m_Rect` and `m_RD.textureRectOffset` were recovered by streaming just `sharedassets4.assets` out of the bundle. The web uses separately restored transparent frames in `tool-aligned`: for example, marker bottom is 214 × 90 at (2, 38) within a 216 × 128 frame, while marker main is 207 × 115 at (9, 3). Pencil and fill layers are restored using their own original frames and offsets as well. Coordinates are rounded to the pixel boundaries used by the original UnityPy PNG crop; visual parity still needs user confirmation.

The same cropped-export issue affected the main tools and eraser icons. Their serialized sprite frames are 214 × 214, but the exported icon-tool image is 145 × 158 at (35, 27), and icon-elastic is 133 × 119 at (46, 46), using top-origin integer crop coordinates. Their transparent frames are now restored before the button's 214 × 214 image layer is rendered.

A subsequent bounded scan covered the three buttons, their popups and the color selection marker. The backgrounds, strokes, shine, pressed overlay, color mask and selection marker also had cropped exports, so their transparent frames were restored from Sprite rect and textureRectOffset. Button shadow, popup sprites, palette swatch and vertical divider have full-size exports (popup backgrounds have only subpixel crop offsets). This scan checks sprite frame geometry, not every Unity runtime transform, stencil behavior or pixel identity.

`ToolColors` GO 63 component 1636 serializes `buttonMain` as Image 1704 (GO `main`, inside color mask) and `outlineMain` as Image 1625 (GO `outline`, the first colored outline). Metadata-mapped `ToolColors.kb` at 0x154371c applies the same input RGBA to both fields through tween calls (durations 0.25 and 0.125 seconds respectively); the separate `outline (1)` remains the black translucent layer. The web applies CSS color transitions with matching durations; easing is not yet verified. `Palette.OnPointerUp` invokes `ManageTools.ir` (0x1542360), which clears the matching panel-open flag; it then schedules a callback whose complete effects remain unverified.

`Palette.jj` at 0x15448fc calls the shared panel-close function with `mainPalette` and 0.25 seconds. Its binding to the delegate scheduled by `OnPointerUp` has not been independently established. Web color changes use CSS transitions of 250 ms for the fill and 125 ms for the colored outline, matching the durations passed to the two color tweens in `ToolColors.kb`; linear easing is an approximation because the original tween easing was not established.

The BrushPanel's `verticalLine` child uses `popup_vertical_line`, has a 16 × 964 RectTransform, and is anchored to the right center at x = -77.67 within the 329 × 1020 panel. The web draws this separate sprite at the corresponding panel-relative coordinates. The three retained tool entries remain rearranged for the deliberately reduced menu, so their positions are not claimed as original seven-tool layout.

Both popup roots have Image components and no serialized Unity shadow component. The web's additional CSS drop-shadow was removed. The normal button image children use 214/209 scaling relative to their button roots. The color fill now uses nested mask and child layers: Unity has a 214 × 214 mask scaled to 0.98951, with its mask graphic hidden, containing a 209 × 209 child. The web reproduces those relative dimensions with CSS masking; Unity stencil and browser alpha-mask edge behavior may differ.

`Brush.hb` at 0x153e964 updates the `mainColor` image and iterates `outlineColors`. For the color palette branch it multiplies all four components of the selected color by the instance value at offset 0x68 before applying them to the outline. The `Brush` constructor at 0x153f574 initializes this value to 0.75 (constant read from ELF address 0x9aace8). The serialized `outlineColors` lists for marker, pencil and fill point to their outline Images. Their exported outline sprites are white in opaque pixels; the web therefore applies a 75% RGB tint and 75% opacity through the sprite mask.

`Palette.OnPointerDown` (0x15444dc) and `Palette.OnDrag` (0x154462c) inspect the selectable item under the pointer, update the selected item and notify a selection callback; drag updates when the item changes. `Palette.OnPointerUp` (0x15447ac) clears its drag state and initiates closing when its checks pass. Web now updates colors on pointer down/drag and closes on pointer up; keyboard activation remains supported. The exact original hit-testing and animated callback remain distinct and are not claimed identical.

`ManageTools.in` (0x15420d4) starts a scale tween to 1 over 0.25 seconds; the common close function (0x153f1f4) starts a scale tween to 0 for a caller-provided duration, often 0.25 seconds. The native call at 0x191cc84 maps to `DOScale`. The web keeps the panels mounted and scales them over 250 ms, using the serialized pivots: tools (0.922179, 0.726953) and palette (1, 0.479294), converted from Unity's bottom-origin coordinates to CSS's top-origin coordinates. Closed panels are inert and hidden from accessibility. Linear easing and transition interruption are web approximations; original easing, complete callbacks, hit testing and Unity stencil edge rendering are not fully established. The reduced tool layout is intentional and is not claimed to match the original seven-item layout.

Browser checks: `web/tests/drawingControls.browser.js` runs on `?screen=drawing` through the browser's script evaluator and verifies selection, eraser restoration, popup switching, 56 colors, hidden interaction and duration. A real browser drag from Color 3 to Color 4 also selected Color 4 and closed the palette. These checks validate web behavior, not pixel identity or exact original runtime behavior.

Further ARM64 analysis of `Palette.OnPointerUp` reveals a first `DOScale` to zero with the float at ELF virtual address 0x9aab4c, approximately 0.3 seconds. It immediately clears the panel-open flag and attaches a completion delegate; `Palette.jj` invokes the common 0.25-second close routine, but the delegate's binding has not been proven. The web now uses 300 ms for a color selection and 250 ms for opening or closing via the main controls.

Both open and common-close code first call `DOKill` on the transform, then pass the integer 1 to a generic tween-settings function at 0x1a3a778. Its instructions store the supplied value in the tween and call `IsFlashEase`. Metadata identifies `TweenSettingsExtensions.SetEase(T, DG.Tweening.Ease)` and the `DG.Tweening.Ease` enum. In this metadata's `fieldDefaultValues` section, `Unset` (field 52697) and `Linear` (field 52698) point to compressed signed integers 0x00 and 0x02 respectively, decoding to 0 and 1. Together these observations strongly support linear popup easing, though REA cannot directly resolve generic method instances for metadata version 39. This does not establish the easing of `ToolColors.kb`: its two `DOColor` tweens are inserted into a `Sequence` and no explicit `SetEase` appears in that method. The web's linear color transitions remain an approximation.

The DOTween static constructor at 0x1919528 initializes the static field at offset 0x54 to 6, consistent with `defaultEaseType` in the metadata field order; enum field defaults decode 6 as `OutQuad`. `Sequence.Setup` at 0x1919284 sets its own ease field at offset 0xb4 to 1 (`Linear`). This supports linear sequence timing with normally OutQuad child color tweens, but does not establish the effective runtime setting: DOTween settings or application code may override the default. The existing object inventory identifies a `DOTweenSettings` script but does not establish the absence of a serialized settings object; an attempted full UnityPy scan of the bundled data was terminated by the system (exit 137). Do not treat the initializer alone as proof of the running app's color easing; the web color transition remains unchanged pending stronger evidence.
