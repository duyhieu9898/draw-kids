# Gallery scrolling: evidence and reconstruction

The v3.141 IL2CPP metadata identifies `DynamicGalleryMenu` fields `_content`, `_packs` and `_galleryMenu`, `GalleryMenu` fields `galleryPacks`, `galleryMenuScroll`, `bgColors`, `bg`, and `fg`, and `ManageGalleryMenuScroll` fields `_galleryMenu` and `_panels`. These declarations alone do not establish the precise looping algorithm or the ordering of every item. `GalleryMenu.kz` (0x1546e9c) reads a color by index from `bgColors` and calls Unity `DOColor` on `bg` with a duration of 0.75 seconds. The background transition duration is reproduced in the web; its easing remains unverified.

`GalleryMenu.la` (0x1546b4c) calls `GalleryMenu.ld` (0x15476f8) after setting up the gallery. The latter obtains `sizeDelta.x` from the first panel in the gallery scroll component, multiplies it by -0.25, and passes that absolute local-X destination and 1.0 second to DOTween `DOLocalMoveX` (0x191c458). This establishes the tween duration and destination relative to that panel's width, but not the initial local position or the precise mapping of the native panel to the web layout. No explicit ease is set by `ld`; DOTween's static default is OutQuad but application settings may override it.

The web implements the user's described continuous gallery using three copies of the available topic sequence, moving the scroll position by one full cycle near either edge. On entry it animates for one second over 25% of the web topic section width, ending centered on the selected topic; OutQuad is an approximation based on the DOTween initializer. Exact starting position, web-to-native panel dimensions, runtime easing, infinite-scroll pooling algorithm and topic order remain unverified. Background changes use the topic nearest the viewport center. Selecting a picture passes its own topic ID to the drawing screen and saved thumbnails use the topic and picture ID.

The web's drawing masks currently come from the v3.101 asset catalog, whose documented topic order is Animals, Dolls, School, Music, Vehicles, Food, Halloween, Christmas. The v3.141 menu product order places Halloween and Christmas at topic IDs 8 and 9; the shared asset mapping therefore maps those IDs to v3.101 packs 7 and 8. IDs 7 and 10–12 have no established matching drawing data and are disabled, rather than silently loading another picture. Existing saves for the remapped IDs remain in IndexedDB under their old keys; corrected drawings use `mapped-v2:` keys so older content is not overwritten or applied to a different picture. The complete v3.141 mapping and original topic order are still unverified.

## 3.141 artwork inventory and cross-version checks

`reports/v3.141/gallery-art-mapping.json` records all 12 serialized menu products and 160 numbered preview candidates, with original file and path IDs for associated outline and region sprites. Numeric group and picture identifiers are taken from names, not assumed to be the runtime `ProductTypes` binding. Groups 1–8 each have 16 named outlines and region sets; group 9 has 16 outlines but its picture 16 has no matching numbered region sprites; group 10 has 16 previews but no matching numbered outline or region sprites in the inventory. Resource dependencies or nonstandard names could exist outside this bounded search.

An automated image-data comparison (`scripts/compare_gallery_versions_v3141.py`, report `reports/v3.141/gallery-cross-version-similarity.json`) compares 3.141 previews against the older web outlines using downsampled grayscale difference. With a strict heuristic threshold, groups 1–8 yield respectively 8, 8, 6, 9, 11, 4, 11 and 9 unambiguous same-number matches out of 16; groups 9–10 yield none. The remaining items cannot be identified by this heuristic and are not proven different or identical. This supports several cross-version links but does not prove all picture or topic bindings.

`resources.assets` and its external texture resource were extracted selectively from the UnityFS bundle for analysis. In a trial with group 1 picture 1, simply expanding the trimmed 3.141 region sprites to their 1024 × 1024 frames and scaling to the web canvas did not align reliably with the older masks. `m_Rect`, pixel-per-unit and runtime paintable transforms therefore need to be followed before bulk importing 3.141 masks. No 3.141 drawing masks were enabled on the basis of this trial.

Further geometry check: group 1 picture 1's outline spans 1076 pixels at 100 pixels per unit, while its region sprites span 1024 pixels at approximately 43.2615 pixels per unit. Reconstructing the trimmed sprites and scaling each region by `775 / ((outlineWidth / outlinePPU) * regionPPU)` around the shared center yielded approximately 0.977–0.994 binary alpha intersection-over-union against the corresponding older web masks for the first ten region sprites; the outline yielded approximately 0.991. This validates a promising transform on that sample, not every picture or the native runtime. `scripts/stage_art_v3141.py` uses that transform to stage 15 group-9 candidates under the ignored extracted directory. Candidate 9-16 has an outline but no matching numbered regions. The staged set has not been assigned to a web topic because the runtime product-to-asset-group binding remains unproven.
