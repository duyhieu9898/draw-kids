# React Native app

Expo + Expo Router + Skia scaffold, currently a vertical slice: 12 topics x 16 pictures (192 pictures, 2552 regions) extracted from 3.141, menu → gallery → drawing screen, fill/stroke/eraser/undo, saved to SQLite and re-opened. Intro Spine 3.8.99 runs in a WebView, intro and BGM/effects audio play natively via `expo-audio`. The user confirmed the intro and intro audio work well. Menu, gallery and drawing bar UI use PWA sprites; continuous scroll background change and the star burst on release have been implemented per user confirmation, not yet verified on device. Topic grid motion and scaling are temporarily disabled due to a bug and will be re-checked later.

Topic folders and codes use `animals`, `dolls`, `school`, `music`, `vehicles`, `food`, `halloween`, `christmas`, `insects`, `dinosaurs`, `ocean`, `magic`. Drawing keys use the topic name; data saved under `pack2`–`pack8` can no longer be opened. Labels and topic/picture ordering still need to be matched against the original app at runtime; resources and limits are documented in [12-topic data](../docs/THEME_DATA_GAP.md).

- `src/app/` — Expo Router routes (`index` is the 12-topic menu, `topics/[pack]` is the gallery by group, `draw/[pack]/[picture]` is the drawing screen, `dev/orientation` keeps the old landscape-lock check screen).
- `src/audio/sound.ts` — BGM + effects via `expo-audio` (8 clips copied from the original assets, triggered per the PWA; details N14 in the tracker).
- `src/intro/` — intro Spine 3.8.99 running in `react-native-webview` (npm only ships spine-core 4.x, so native can't be used in Expo Go). The animation HTML is generated by `npm run intro` from `assets/intro/`; audio is loaded natively and played when the animation starts, with a timeout to continue if it fails to load. Edit intro assets, then re-run the command. The web export skips the intro because react-native-webview has no web build.
- `src/domain/`, `src/drawing/`, `src/storage/`, `src/assets/` — pure logic, Skia engine, SQLite and catalog. Gallery thumbnails are 264×264 PNGs written to `documentDirectory/thumbnails/`; SQLite only stores the path (legacy records using base64 are still readable).
- `assets/pictures/<pack>/<picture>/` — verified picture data; `npm run catalog` generates `src/assets/catalog.generated.ts`.

Run `npm ci`, `npm run catalog`, then `npm start`. `npm test` checks geometry and catalog integrity (12×16 pictures, 2552 regions, bounds/mask). The web export is only for viewing the menu/gallery; the drawing screen does not render on web because CanvasKit needs `LoadSkiaWeb`, so drawing must be verified on a device. Add a picture by copying `picture.json`, `outline.png`, `region-*.png` into `assets/pictures/` and re-running catalog. PWA IndexedDB data does not appear in the native app automatically.
